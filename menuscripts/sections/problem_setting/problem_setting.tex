\section{Problem Setting and Benchmark Definition}
\label{sec:problem}

We evaluate early-warning detectors on simulated trajectory data from three
dynamical systems. Each detector receives a trajectory and produces a score
sequence. The score at time \(t\), denoted \(p_{i,t}\), is interpreted as the
detector's warning score for trajectory \(i\). Higher values indicate stronger
evidence for an approaching transition.

The benchmark is defined to compare observer behavior across regimes rather
than to select a single global winner. All reported comparisons use the same
systems, data sizes, seed order, thresholding rule, and evaluation metrics.

\subsection{Dynamical Systems}
\label{sec:systems}

The benchmark contains three synthetic systems, each representing a distinct
bifurcation mechanism.

\begin{description}[style=unboxed,leftmargin=0pt]
  \item[Fold.]
  A saddle-node bifurcation in which a stable equilibrium is lost as the
  control parameter crosses zero. It tests whether an observer can detect
  gradual loss of stability without relying on oscillatory structure.

  \item[Hopf.]
  A supercritical Hopf bifurcation producing an oscillatory instability. It
  tests whether an observer can exploit the temporal structure associated with
  emerging oscillation as the system loses stability.

  \item[Logistic.]
  The logistic map undergoes period-doubling as the control parameter
  increases through \(\mu = 3\). It tests whether an observer calibrated on
  continuous warning scores also handles discrete-time, map-like dynamics.
\end{description}

These systems are not interchangeable datasets. They are distinct test cases
for the same observer family. The system equations and parameter values are
listed in Appendix~\ref{sec:appendix:systems}.

\subsection{Trajectory Data and Training-Set Sizes}
\label{sec:data}

For each system, the benchmark generates two trajectory types. Signal
trajectories contain a transition; the bifurcation time \(\tau_i\) marks the
step at which the control parameter crosses the critical value. Null
trajectories hold the control parameter fixed in the stable regime, providing
non-transition examples for false-positive evaluation.

The training-set size (referred to as patient count in the codebase) denotes
the number of simulated trajectories used per benchmark condition. The
reported sizes are
\[
  n \in \{100, 200, 300, 400, 500\}.
\]
For each size, system, and observer variant, results are aggregated over ten
seeds:
\[
  101,\; 202,\; 303,\; 404,\; 505,\; 606,\; 707,\; 808,\; 909,\; 1010.
\]
These seeds are generated deterministically as \(101 \cdot k\) for
\(k = 1, \ldots, 10\). Each seed controls data generation, model
initialization, and data splitting.

The benchmark compares two learned observer variants:
\(\text{Kalman-BCE}\) and \(\text{Kalman-LSTM-Spec}\). Each produces test
scores \(p_{i,t} \in [0,1]\), which are used for threshold selection,
detection-time computation, early-warning AUC, and false-positive evaluation.

\subsection{Batch Selection}
\label{sec:batch}

The experiment directory can contain multiple result batches for the same
training-set size, including partial reruns from development. To ensure
reproducible reporting, the analysis uses a deterministic selection rule. For
each size \(n\), let \(\mathcal{B}_n\) be the set of available batches. The
selected batch maximizes, in order:

\begin{enumerate}[leftmargin=*]
  \item the number of unique \((\text{system}, \text{method}, \text{seed})\)
        triples,
  \item the number of systems represented,
  \item the total number of result records,
  \item the batch timestamp, as a tiebreaker.
\end{enumerate}

This rule retains the most complete batch per training-set size and excludes
partial reruns from all reported figures and tables. The full batch inventory
is listed in Appendix~\ref{sec:appendix:batches}.

\subsection{Evaluation Metrics}
\label{sec:metrics}

The benchmark reports three metrics: detection time, early-warning AUC, and
false-positive rate. These metrics measure different properties of the same
score sequence and should not be collapsed into a single ordering.

\subsubsection{Detection Time}
\label{sec:metrics:dt}

For a signal trajectory \(i\) with bifurcation time \(\tau_i\), define the
first pre-bifurcation alert time as
\[
  a_i = \min \{t : 0 \leq t < \tau_i,\; p_{i,t} \geq \theta \},
\]
where \(\theta\) is the decision threshold. If such an alert exists, the
trajectory-level detection time is
\[
  DT_i = \tau_i - a_i.
\]
Higher values indicate earlier detection. The reported detection time is the
mean of \(DT_i\) over signal trajectories with at least one pre-bifurcation
alert. Trajectories without a pre-bifurcation alert are excluded from this
mean rather than counted as zero-lead detections.

\subsubsection{Early-Warning AUC}
\label{sec:metrics:auc}

For each signal trajectory, the early-warning score is the maximum model
score in a window before the bifurcation:
\[
  e_i = \max \{p_{i,t} : \max(0,\tau_i - 50) \leq t < \max(0,\tau_i - 5)\}.
\]
For each null trajectory \(j\) with sequence length \(T_j\), the
corresponding score is computed over the terminal portion of the sequence:
\[
  n_j = \max \{p_{j,t} : \max(0,T_j - 50) \leq t < \max(0,T_j - 5)\}.
\]
The early-warning AUC is the area under the ROC curve computed from the
pooled signal scores \(\{e_i\}\) and null scores \(\{n_j\}\), with labels
one for signal and zero for null.

\subsubsection{False-Positive Rate}
\label{sec:metrics:fpr}

The false-positive rate is computed on null trajectories as a per-time-step
alert rate:
\[
  \mathrm{FPR} =
  \frac{\sum_j \sum_{t=0}^{T_j-1} \mathbf{1}[p_{j,t} \geq \theta]}
       {\sum_j T_j}.
\]
This quantity measures the fraction of null time steps that would trigger an
alert. It is not a per-trajectory false-positive probability.

\subsubsection{Threshold Selection}
\label{sec:metrics:threshold}

Thresholds are selected on the validation split before test evaluation. For a
signal validation trajectory, scores in the window
\[
  \max(0,\tau_i - 60) \leq t < \tau_i
\]
are labeled positive. Scores in the early pre-bifurcation region
\[
  0 \leq t < \max\bigl(0,\; \max(0,\tau_i - 120) - 1\bigr)
\]
are labeled negative. If null validation trajectories are available, their
first 120 time steps are also labeled negative. In the benchmark runs
reported here, only signal validation trajectories are used for threshold
selection; null validation scores are not supplied to the threshold routine.

The threshold is chosen from the validation ROC curve by maximizing Youden's
statistic \citep{youden1950index}, \(J = \mathrm{TPR} - \mathrm{FPR}\). If
the sensitivity at the selected threshold is below 0.80, the threshold is
shifted to the operating point whose sensitivity is closest to 0.80. If the
validation labels contain only one class, or if the validation scores have
effectively zero variance, the fallback threshold is 0.5.
